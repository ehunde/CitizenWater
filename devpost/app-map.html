CitizenWater · project map

How a report moves through the app

CitizenWater lets a person record a water problem, keep it on their phone, share a private report link through their own email app, and record follow-up. The browser app handles the screens and local copy; the Express server connects to Supabase for the shared report and photo.

One real flow: save a report

After the citizen submits the report form, it is saved in IndexedDB and then appears in the active report list. Opening the email draft is a separate, user-initiated cloud-share and handoff step.

Reference route through the code

This is a navigation guide, not a claim that a live code tour was completed.

Form submission

In public/js/app.js, search for reportForm.addEventListener('submit'. This collects the reviewed report and invokes local saving.

Local persistence

In public/js/storage.js, open saveReport. IndexedDB stores the report and photo so pending work survives reloads on that device.

Visible result and sharing

Back in public/js/app.js, refreshReports renders saved reports. For a separate, intentional handoff, follow openEmailDraft to preparePrivateShare; server.js connects to Supabase.

To change this, start here

Report screens and actions: public/index.html and public/js/app.js.
Responsive visual style: public/styles.css.
Offline report storage: public/js/storage.js. Avoid putting secrets or private API data in the service-worker cache.
Cloud report/photo links: server.js and server environment settings; the Supabase service key stays server-side.
Sample utility matching: src/data/utilities.json and public/js/utility-matcher.js. Directory coverage is limited and labeled as sample data.

A practice to reuse

Turn a broad requirement into a visible result and a check. In this project, “opening a draft does not mean it was sent” became a clear Pending state until the citizen returns and marks it sent. That criterion guided the email handoff and offline checks recorded in devpost/checklist.md. On another app, define what the user should see after each important action before implementing it.

Run and source snapshot

Use Node.js 24, configure the server-side values from .env.example in a local .env, then run npm start from the project folder and open http://localhost:3000. On Render, use the deployed HTTPS address. Never publish the local .env.
